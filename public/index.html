Fair to the buyer. Fair to the seller.

Escrow usually forces a yes or no. Real work is rarely all right or all wrong, so ProofPay pays the part that is proven and keeps the rest safe.

Agree on “done” before any money is held

Both sides write the checklist first. Each item has a weight, so each item has a price. Nobody can move the goalposts later, including the AI.

The AI judges. The code counts.

The AI answers pass or fail for each item and gives a reason. The score and the payout are calculated in code from your weights, so a clever message in the delivery can’t talk its way to a full payment.

Pay for what is finished

Verified items are paid right away through a PayPal partial capture. The rest stays held until the seller fixes it. If the deadline passes, the held money goes back to the buyer.

Built for deals between people who haven’t met

Freelance milestones

Stop choosing between paying upfront and delivering unpaid. The money is already held, and each finished piece unlocks its share.

Small-business orders

Buy from a new supplier with less worry. Release payment as the goods and paperwork you asked for show up.

AI agents that spend for you

Give an agent a budget and a checklist through the API. It can’t overpay, because nothing is captured until delivery is verified.

A record you can point to

Every hold, verdict, payment and refund is logged with a time, so a disagreement starts from facts instead of memory.

From agreement to payout in five steps

  1. Write the mandate

    Set the task, the budget, the deadline and the weighted checklist.

  2. Hold the funds

    The buyer approves a PayPal authorization. Money is reserved, not sent.

  3. Deliver

    The seller submits evidence: a link, test output, tracking details or notes.

  4. Audit

    The AI checks each item against the evidence and explains every verdict.

  5. Release

    The verified share is captured now. The rest waits for a fix or goes back.

Questions people ask first

What if the AI gets a score wrong?

It can only judge the checklist both sides agreed to, and it shows its reason for every item. The seller can resubmit better evidence at any time. A button to ask a person to review a contested score is on the roadmap but is not built yet.

What happens if the seller never delivers?

The buyer closes the mandate, or the deadline passes, and the remaining authorization is voided. The held amount is never captured.

Does real money move?

No. This project runs on the PayPal sandbox with test accounts. It is a working prototype built for the PayPal AI Hackathon, not a live payment service.

Which PayPal features does it use?

Orders with the authorize intent, then the Payments API for partial captures and voids. The code is open source, so you can read exactly how each call is made.

Can it handle physical goods?

Today the seller submits tracking details or notes as text, and the AI checks them against your checklist. Automatic carrier and website checks are the next thing to build.
